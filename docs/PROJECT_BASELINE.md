# Shift-Helper — проектный baseline

## 1. Масштаб продукта

Shift-Helper — небольшое автономное приложение для узкого круга сменного персонала Кочубеевской ВЭС.

Проект не предполагает обязательного сервера, доменной инфраструктуры, контейнеров, системных служб или прав администратора.

## 2. Обязательные свойства

- одна кодовая база;
- отдельные переносимые сборки Windows x64 и Linux x64;
- запуск без установщика и повышения прав;
- локальный веб-интерфейс на `127.0.0.1`;
- работа без интернета;
- SQLite как первичное локальное хранилище;
- данные находятся отдельно от программных файлов;
- обновление программы не должно затрагивать базу;
- экспорт журналов и рапорта в `.xlsx`;
- подключаемые источники импорта.

## 3. Первичные модули

1. Журнал событий.
2. Журнал работ по нарядам и распоряжениям.
3. Утренний рапорт на 07:00.
4. Справочник кодов ошибок ВЭУ.
5. Замена предохранителей ТН.
6. Осмотры КТП.
7. Нагрузка трансформатора.
8. Импорт, экспорт и резервное копирование.

## 4. Утверждённые предметные правила

### 4.1. Наряды

Формат номера: `NN-MM/КВЭС`.

- счётчик начинается с 1 каждый месяц;
- номер определяется по дате регистрации;
- минимальная разрядность порядкового номера — два знака;
- после `99` используются `100`, `101` и далее;
- удаление записи не освобождает номер.

### 4.2. Распоряжения

Формат номера: `Nр`.

- сквозная нумерация в пределах календарного года;
- 1 января счётчик начинается заново;
- счётчик не связан с нарядами;
- удаление записи не освобождает номер.

### 4.3. Отчётный интервал утреннего рапорта

- начало: 07:00 предыдущего дня включительно;
- конец: 07:00 текущего дня не включительно.

### 4.4. Ограничение по оборотам и `P ремонт`

| Ограничение | `P ремонт`, МВт |
|---:|---:|
| ≥ 0,95 | 0 |
| 0,90 | 0,55 |
| 0,85 | 0,75 |
| 0,80 | 1,00 |
| 0,75 | 1,20 |
| 0,70 | 1,40 |
| < 0,70 | 2,50 |
| прочее | 0,45 |

Таблица является утверждённой бизнес-логикой.

## 5. Хранение данных

По умолчанию приложение использует пользовательский каталог ОС:

- Windows: каталог локальных данных пользователя;
- Linux: `~/.local/share/Shift-Helper` или эквивалент платформы.

Внутри создаются:

- `data/shift_helper.sqlite3`;
- `exports/`;
- `backups/`;
- `imports/`;
- `logs/`.

SQLite-файл нельзя использовать как общую одновременно открытую базу на сетевом диске.

## 6. Почтовые адаптеры

Первая версия должна поддерживать:

1. ручную загрузку файла;
2. drag-and-drop;
3. контролируемую папку;
4. Outlook Classic на Windows как дополнительный адаптер.

Будущие варианты:

- IMAP;
- Microsoft Graph;
- иной корпоративный API;
- `.eml` и локальный почтовый клиент.

Парсер вложения не должен зависеть от способа получения файла.

## 7. Первый вертикальный срез

Первый рабочий прототип включает:

1. переносимый локальный запуск;
2. SQLite в пользовательском каталоге;
3. журнал событий;
4. быстрый ввод;
5. справочник кодов ошибок;
6. ограничения ВЭУ;
7. расчёт `P ремонт`;
8. экспорт журнала событий в `.xlsx`;
9. резервное копирование.

## 8. Запрещённые упрощения

- не использовать Excel или Calc как первичную базу;
- не кодировать статусы только цветом;
- не удалять исторические производственные записи физически;
- не привязывать ядро к Outlook;
- не требовать системного Python;
- не требовать `sudo` или прав администратора;
- не хранить реальные книги, письма, базы и персональные данные в GitHub.

# UX-GRID-001 — spreadsheet workspace core

Статус: повторный проверочный кандидат после эксплуатационной проверки

Цель — заменить временную самописную contenteditable-таблицу полноценной локальной spreadsheet-сеткой, сохранив структуру исходного журнала событий.

## Обязательный контракт

- журнал занимает доступную высоту рабочего окна;
- визуально непрерывная сетка с запасом пустых строк;
- пустые строки не создают записи в SQLite до ввода данных;
- дата и время автоматически появляются только в фактически редактируемой строке;
- изменение ширины и порядка колонок сохраняется локально;
- выравнивание задаётся по колонкам по умолчанию и меняется для выделенных ячеек;
- доступны ручная заливка и правила автоматического выделения;
- закреплены номер строки и ключевые начальные колонки;
- диапазоны и строки выбираются мышью и клавиатурой;
- копирование и вставка совместимы с Excel/Calc через TSV;
- общий поиск и фильтры по колонкам;
- автоподстановка оборудования, описаний, причин, действий, исполнителей и авторов;
- дата, время, `!`, `.`, `+N` и компактный ввод обрабатываются до сохранения;
- печать символа в выделенной ячейке сразу запускает ввод;
- Enter завершает редактирование, Shift+Enter создаёт перенос в многострочном поле;
- текстовый редактор расширяется по содержимому и не обрезает ввод;
- доступно заполнение выделенного диапазона вниз и вправо;
- сохранение записи выполняется без кнопок создания;
- структура пользовательского листа не меняется без явного согласования.

## Расчёт потерь

Источник — исходная книга `Журнал событий актуальный 2026.xlsm`.

Формула колонки `Потери от простоя (руб.)`:

```text
простой в часах × 2500 руб.
```

Поле рассчитывается автоматически после заполнения даты и времени пуска и не редактируется вручную.

## Техническая основа

- Tabulator 6.5.2, закреплённый локально в исходном коде;
- библиотека поставляется внутри переносимой сборки без CDN и сетевой зависимости;
- SHA-256 локальных frontend-ресурсов проверяется в CI;
- серверные API и SQLite остаются источником истины;
- ширины, порядок, фильтры, выравнивание, заливки и условные правила хранятся отдельно от оперативных данных;
- реальный Chromium smoke-тест проверяет прямой ввод, Enter/Shift+Enter, отсутствие ложных дат, расчёт потерь, заливку, сохранение и поиск.

## Граница текущего кандидата

- стилистическая доводка тёмной темы отложена до стабилизации функционального контракта;
- автоматическое распознавание кодов ошибок и предметные текстовые шаблоны относятся к следующему этапу;
- окончательная клавиатурная эргономика и построчный clipboard-контракт принимаются только после повторной проверки оператором.

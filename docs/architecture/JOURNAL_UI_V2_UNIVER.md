# ARCH-002 — Journal UI V2 on Univer Sheets OSS

Status: **ACCEPTED**  
Date: 2026-07-29  
Baseline: `main` / `fafd3a520ddf7109d502510040ee0941cf1bb041`

## Decision

The event journal frontend is rewritten as a new clean implementation on:

- TypeScript;
- Univer Sheets OSS;
- stable aligned `@univerjs/*` package version `0.25.1`;
- Vite build output embedded into the existing Flask portable application.

This is the **only** target spreadsheet engine for Journal UI V2.

Tabulator and Handsontable are not fallback implementations and are not allowed in the new runtime.

## Preserved product foundation

The rewrite does not replace:

- Python and Flask;
- SQLAlchemy and SQLite;
- domain validation and journal business rules;
- record `revision` semantics;
- portable Windows x64 and Linux x64 packaging;
- the `.xlsx` compatibility mirror generated by Python/openpyxl;
- the planned manual-launch LAN mode.

SQLite remains the primary source of operational data. Univer workbook state is a presentation and interaction model, not a second independent database.

## Clean-room boundary

The new frontend starts from stable `main`, not from rejected PR #5.

Allowed inputs from the rejected frontend:

- approved column meanings and order;
- operator requirements;
- visual references;
- regression scenarios;
- icons and neutral design tokens after explicit review.

Forbidden inputs:

- old event-journal JavaScript runtime files;
- acceptance/compat/repair/fallback controllers;
- global `window.shiftHelper*` state;
- MutationObserver-based state repair;
- Tabulator-specific state and DOM contracts;
- CSS copied as an accumulated cascade.

## Runtime ownership

```text
Univer Sheets
    presentation, editing, selection, clipboard, fill, styles, zoom
            |
            v
ShiftHelperSheetAdapter
    row/column mapping, command filtering, record identity, revision
            |
            v
Flask JSON API
    validation, concurrency control, audit, persistence
            |
            v
SQLite (primary) -> openpyxl -> approved .xlsx mirror
```

A visual row number is never a record identity. Each journal record keeps its stable database identifier and revision independently of sorting, filtering, insertion, or deletion in the sheet.

## First vertical slice

The first delivery is deliberately narrow:

1. a separate `/events/v2` page;
2. Univer Sheets bootstrapped from a Vite bundle;
3. real event records loaded from a read-only Flask snapshot endpoint;
4. approved event columns and basic cell types;
5. no old frontend scripts or styles loaded;
6. TypeScript strict check and frontend production build in CI;
7. portable builds compile frontend assets before PyInstaller packaging.

Editing persistence, LAN synchronization, audit, and `.xlsx` updates are added only after this clean read-only slice is proven.

## Quality gates

- all `@univerjs/*` packages use the same exact version;
- no alpha, beta, insiders, caret, or tilde versions;
- TypeScript runs in strict mode;
- generated assets are reproducible CI output and not hand-edited;
- the Flask application fails clearly when frontend assets are missing;
- backend tests remain independent of Univer internals;
- browser tests operate through visible interactions and Facade API state, not readiness flags alone.

## Non-goals

- Univer Pro server;
- Univer built-in `.xlsx` import/export;
- Univer built-in printing;
- realtime collaboration server in the foundation slice;
- formulas, charts, pivot tables, Docs, or Slides;
- migration of PR #5 runtime code.

# UNO-001 — пользовательское расширение LibreOffice Calc

Status: **AUTOMATIC LISTENER CANDIDATE / WINDOWS RUNTIME TEST REQUIRED**  
Issue: `#9`  
Base: `main` / `d361ff0a108a762fd4d410c0af8fc8a2967b5d8c`

## Решение

Адаптер LibreOffice выполняется внутри процесса Calc как пользовательское
Python-расширение `.oxt`. Расширение получает текущий документ через
`XSCRIPTCONTEXT`; переносимый EXE остаётся самостоятельным режимом генерации
рапорта.

## Доказанный runtime-блокер ручной схемы

Windows LibreOffice подтвердил, что после обычного ввода Calc успевает преобразовать
исходные токены до запуска ручного макроса:

- `+1` становится формулой/числом;
- `0708` и `3102` становятся числовыми значениями и отображаются как старые даты;
- исходный текст невозможно надёжно восстановить постфактум.

Поэтому основной путь UNO-001 изменён с ручной нормализации выделения на listener,
который подготавливает ячейку до ввода.

## Автоматический кандидат 0.3.0.dev2

Расширение экспортирует отдельный скрипт `shift_helper_auto.py`:

- `enable_automatic_input`;
- `disable_automatic_input`;
- `automatic_input_status`.

После `enable_automatic_input` selection listener отслеживает выбранный диапазон в
`B`, `C`, `I` или `J` листа `ЖС`. Пустые ячейки выбранного диапазона и буфер из 256
строк ниже получают текстовый формат `@`, поэтому Calc сохраняет исходные токены.
Document modify listener после подтверждения ввода применяет quick-input core и
записывает числовую дату/время. Нормализация добавляется как hidden undo action.

Ошибочный токен остаётся текстом и показывается оператору. При отключении listener
пустые подготовленные ячейки получают исходный формат обратно.

## Граница безопасности

- расширение не обращается к сети;
- рабочие книги и оперативные данные не входят в OXT;
- listener действует только для текущей книги и листа `ЖС`;
- строка заголовков не изменяется;
- формулы не используются как предыдущее корректное значение;
- сохранение книги остаётся явным действием оператора;
- закрытие LibreOffice уничтожает сессионный listener;
- merge запрещён до реальной проверки Windows/LibreOffice.

## Ручная проверка 0.3.0.dev2

1. Обновить расширение и полностью перезапустить LibreOffice.
2. Открыть копию журнала и лист `ЖС`.
3. Выбрать пустую ячейку в `B` и запустить `enable_automatic_input` один раз.
4. Ввести обычным способом, без апострофа: `.`, `+1`, `3102`, `0708`.
5. Проверить автоматическое преобразование корректных токенов и сохранение
   ошибочного `3102`.
6. Повторить для времени: `.`, `+20`, `2500`, `930`.
7. Проверить переход `23:50` + `+20` с увеличением парной даты.
8. Вставить несколько строк текста в одну выбранную ячейку.
9. Проверить `Ctrl+Z`, `Ctrl+Y`, сохранение и повторное открытие.
10. Проверить Enter, Tab и переход мышью.

## Пока не входит

- автоматическое включение listener при открытии книги;
- собственная кнопка/панель Shift-Helper;
- генерация рапорта из Calc;
- импорт генерации из почты;
- очистка legacy Flask/SQLite;
- журнал работ.

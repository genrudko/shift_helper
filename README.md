# Shift-Helper

Shift-Helper автоматизирует рабочие книги сменного персонала Кочубеевской ВЭС и
формирование утреннего рапорта.

## Текущая архитектура

- **LibreOffice Calc** — рабочий табличный интерфейс оператора;
- существующая книга журнала событий — первичный рабочий документ;
- **Python Shift-Helper Core** — проверка, нормализация, отбор данных и генерация
  новых `.xlsx`-файлов;
- новый рапорт формируется как отдельная копия утверждённого шаблона для ручной
  загрузки на закрытый сайт;
- пользовательское `.oxt`-расширение подключает функции ядра непосредственно к Calc.

Собственный Excel/Calc-подобный интерфейс, Univer Sheets и SQLite как первичное
хранилище больше не являются целевой архитектурой.

## Принятая база

### PIVOT-001

Базовый Python-контур читает `ЖС`, проверяет числовые даты и время, воспроизводит
окно рапорта `07:00–07:00`, утверждённый фильтр VBA и формирует проверяемый `.xlsx`.

### UNO-001

Расширение Calc поддерживает автоматический быстрый ввод в столбцах `B/C/I/J`,
переход через полночь, единый Undo/Redo и перехват `.uno:Paste` до распознавания
значений самим Calc.

### UNO-002

Операторские команды публикуются через пристыкованную Calc add-on toolbar и
обслуживаются Python UNO-компонентом `ru.kves.shifthelper.calc.controls` без
LibreOffice ScriptProvider.

## FULL-TEST-001 — срочный интегрированный кандидат

Версия `0.4.0.dev0` объединяет накопленные решения в один тестовый контур:

1. **Подготовить полный контур рапорта** — создаёт или проверяет листы:
   - `Ввод - Основные`;
   - `Ввод - Команды`;
   - `Ввод - Нарушения`;
   - `Ввод - Состояние ВЭУ`;
   - `Ввод - Работы`;
   - `Ввод - Дефекты`.
2. Таблица состояния предварительно содержит 84 ВЭУ и коммерческие группы ГТП.
3. При подготовке можно выбрать последний новый рапорт и перенести его текущие
   значения в рабочие листы журнала.
4. **Импортировать генерацию** ищет вложение классического Outlook
   `Генерация КВЭС за вчера_dd_mm_yyyy.xlsx`; при недоступности Outlook позволяет
   выбрать файл вручную. Используются `Сумма ВЭС!G26`, `Q26` и проверка `Q2:Q25`.
5. **Сформировать полный утренний рапорт** заполняет все семь листов нового шаблона:
   - `Основные данные`;
   - `Аварийные отключения ЛЭП`;
   - `Команды по внешней инициативе`;
   - `Нарушения ОТиПБ + Экология`;
   - `Состояние ВЭУ`;
   - `Запланированные работы`;
   - `Дефекты оборудования`.
6. Аварийные отключения читаются из `ЖС` по принятому окну и фильтру.
7. Запланированные работы разворачиваются по отдельным ВЭУ только при примечании
   о вводе на ночь или выходные.
8. Результат формируется в скрытой pending-копии, проверяется и только затем
   публикуется отдельным `.xlsx`; журнал и шаблон не перезаписываются.

Для ускорения оперативного теста полный report-runtime временно хранится в OXT как
детерминированный сжатый loader. Сборка CI распаковывает, компилирует и проверяет
полный исходник. После стабилизации runtime этот технический долг должен быть
убран отдельным рефакторингом.

## Сборка расширения

```powershell
python scripts/build_calc_extension.py
```

Результат:

```text
dist/Shift-Helper-Calc-FULL-TEST-001.oxt
```

Реальные рабочие книги, письма, базы, ФИО и оперативные данные запрещено
публиковать в репозитории.

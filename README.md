# Shift-Helper

Shift-Helper автоматизирует рабочие книги сменного персонала Кочубеевской ВЭС и
формирование утреннего рапорта.

## Текущая архитектура

- **LibreOffice Calc** — рабочий табличный интерфейс оператора;
- существующая книга журнала событий — первичный рабочий документ;
- **Python Shift-Helper Core** — проверка, нормализация, отбор данных и генерация
  новых `.xlsx`-файлов;
- новый рапорт формируется как отдельная копия утверждённого шаблона для ручной
  загрузки на закрытый сайт;
- пользовательское `.oxt`-расширение подключает функции ядра непосредственно к Calc.

Собственный Excel/Calc-подобный интерфейс, Univer Sheets и SQLite как первичное
хранилище больше не являются целевой архитектурой.

## PIVOT-001

Первый срез умеет:

1. читать лист `ЖС` без изменения исходной книги;
2. проверять числовые даты и время Excel;
3. воспроизводить подтверждённое окно рапорта `07:00–07:00` и фильтр VBA;
4. заполнять только лист `Аварийные отключения ЛЭП` в копии нового шаблона;
5. формировать `event-selection.csv` и `validation.json`;
6. строго разбирать контракт быстрого ввода дат и времени, включая массовую
   вставку и переход через полночь.

Пример запуска:

```powershell
shift-helper build-emergency-report `
  --journal "Журнал событий актуальный 2026!.xlsx" `
  --template "Рапорт НСС Кочубеевская ВЭС от 2026-07-30.xlsx" `
  --report-date 2026-07-30 `
  --output "Рапорт НСС Кочубеевская ВЭС от 2026-07-30.generated.xlsx" `
  --diagnostics diagnostics
```

## UNO-001

Пользовательское расширение Calc собирается командой:

```powershell
python scripts/build_calc_extension.py
```

Результат:

```text
dist/Shift-Helper-Calc-UNO-001.oxt
```

Автоматический режим обрабатывает быстрый ввод в столбцах `B/C/I/J` листа `ЖС`.
Одиночный ввод сохраняется listener-механизмом до распознавания Calc.

Кандидат `0.3.0.dev5` перехватывает команду `.uno:Paste` через
`XDispatchProviderInterceptor`, читает исходный текст из системного буфера обмена и
самостоятельно записывает одноколоночный диапазон. Это выполняется до штатного
распознавания значений Calc. Многоколоночная вставка передаётся Calc без изменений.

## UNO-002

Операторские команды публикуются через Calc add-on toolbar и обслуживаются
Python UNO-компонентом `ru.kves.shifthelper.calc.controls`.

Компонент не использует LibreOffice ScriptProvider. Он определяет каталог
собственного установленного OXT, загружает принятый `shift_helper_auto.py` и его
`Scripts/python/pythonpath` напрямую, передаёт текущую книгу через адаптер
`XScriptContext` и вызывает enable/disable/status внутри одного runtime-модуля.

Панель Calc регистрируется видимой и пристыкованной. Notebookbar LibreOffice не
поддерживает встраивание произвольных групп расширения внутрь ленты, поэтому
поддерживаемый вариант — компактная пристыкованная панель под лентой.

## UNO-003

Команда **«Сформировать утренний рапорт»** запускает принятый срез рапорта прямо
из панели Shift-Helper:

1. оператор вводит дату окончания окна `07:00–07:00`;
2. выбирает утверждённый новый шаблон `.xlsx`;
3. выбирает отдельный путь результата;
4. расширение читает открытую книгу `ЖС` без изменения исходного документа;
5. шаблон открывается скрыто через UNO, проверяется и заполняется на листе
   `Аварийные отключения ЛЭП`;
6. результат повторно открывается для структурной проверки и публикуется атомарной
   заменой временного файла.

Runtime рапорта не использует `openpyxl`: он работает через LibreOffice UNO и
включает только чистые Python-модули событий, фильтра и нормализации строк.

Реальные рабочие книги, письма, базы, ФИО и оперативные данные запрещено
публиковать в репозитории.
